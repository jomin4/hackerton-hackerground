01

클라우드 컴퓨팅이란

정의

항목내용
클라우드 컴퓨팅인터넷을 통해 컴퓨팅 서비스를 제공하는 것
기본 서비스가상 머신, 스토리지, 데이터베이스, 네트워킹
확장 서비스사물 인터넷(IoT), 머신러닝, 인공지능(AI)
핵심 변화물리 인프라의 제약 없이 필요한 만큼 빠르게 쓰고 줄임

특징

특징의미
물리 제약 없음데이터 센터를 직접 짓고 넓힐 필요가 없음
빠른 확장수요에 맞춰 리소스를 빠르게 늘리고 줄임
주문형 프로비저닝필요한 순간에 바로 리소스를 만듦
전 세계 배포공급자의 전 세계 인프라에 배포
지역 복원력여러 지역을 활용해 장애에 대비

기존 데이터 센터 vs 클라우드

항목기존 데이터 센터클라우드
용량 확보구매·설치에 수개월즉시
비용선불 고정 투자수요에 맞춘 지출
축소어려움 (장비가 그대로 남음)사용량을 줄이면 바로 축소
테스트·복구느림빠름
지역 확장지역마다 데이터 센터 필요공급자의 전 세계 인프라 활용

예시: 시즌 상품 출시 (소매 기업)

방식준비시즌이 끝난 뒤
기존몇 달 전에 서버를 구매·설치서버가 놀고 있음
클라우드출시에 맞춰 배포트래픽이 줄면 축소

AWS비교

AzureAWS차이
Azure Virtual MachinesAmazon EC2이름만 다르고 둘 다 가상 머신 임대
Azure StorageAmazon S3, Amazon EBSAWS는 개체·블록 스토리지가 서로 다른 서비스
Azure 지역AWS 리전전 세계 배포·지역 복원력의 단위, 개념 동일

핵심 포인트

이런 질문이 나오면답
클라우드 컴퓨팅의 정의인터넷을 통한 컴퓨팅 서비스 제공
클라우드의 기본 서비스 네 가지가상 머신, 스토리지, 데이터베이스, 네트워킹
시즌 수요에 맞추는 방법필요할 때 배포하고 끝나면 축소
기존 데이터 센터의 용량 확보 시간수개월 (클라우드는 즉시)
02

공유 책임 모델

정의

항목내용
공유 책임 모델보안·운영 책임을 고객과 클라우드 공급자가 나눠 지는 방식
온프레미스모든 책임이 고객 (건물, 전원, 냉방, 장비, 보안까지)
클라우드서비스 유형에 따라 책임이 공급자 쪽으로 이동
이동 방향IaaS → PaaS → SaaS 순으로 고객 책임이 줄어듦

규칙

구분항목담당
항상 고객정보·데이터, 디바이스(모바일·PC), 계정·ID어떤 모델이든 고객
항상 공급자물리적 데이터 센터, 물리적 네트워크, 물리적 호스트클라우드라면 공급자
모델별ID·디렉터리 인프라, 애플리케이션, 네트워크 제어, 운영 체제아래 표

모델에 따라 바뀌는 항목

항목IaaSPaaSSaaS
ID·디렉터리 인프라고객공유공유
애플리케이션고객공유공급자
네트워크 제어고객공유공급자
운영 체제고객공급자공급자

예시

상황고객공급자
클라우드 SQL 데이터베이스 (PaaS)데이터베이스에 넣는 데이터데이터베이스 자체 유지 관리
VM에 SQL 직접 설치 (IaaS)데이터베이스 패치·업데이트, 데이터물리 인프라
함정 · "SaaS라면 데이터 보호도 공급자 책임"은 틀린 말. 정보·데이터, 디바이스, 계정·ID는 SaaS에서도 고객 책임이다.

AWS비교

AzureAWS차이
공유 책임 모델공동 책임 모델AWS는 "클라우드의 보안"(AWS)과 "클라우드 내 보안"(고객)으로 나눠 표현
VM의 운영 체제 패치EC2 게스트 OS 패치둘 다 고객 책임 (IaaS)
Azure SQL DatabaseAmazon RDS데이터베이스 엔진 패치는 공급자, 데이터는 고객

핵심 포인트

이런 질문이 나오면답
모든 모델에서 고객 책임인 것정보·데이터, 디바이스, 계정·ID
클라우드에서 항상 공급자 책임인 것물리적 데이터 센터·네트워크·호스트
IaaS에서 운영 체제 관리고객
PaaS에서 운영 체제 관리공급자
고객 책임이 가장 큰 클라우드 모델IaaS (가장 작은 것은 SaaS)
온프레미스의 책임전부 고객
03

클라우드 모델

정의

모델내용
프라이빗한 조직(엔터티)만 사용하는 클라우드. 자체 데이터 센터, 외부 데이터 센터, 타사 호스팅 모두 가능
퍼블릭타사 공급자가 구축·제어·유지 관리하며 누구나 구매해 사용
하이브리드프라이빗과 퍼블릭을 상호 연결한 환경
다중 클라우드여러 퍼블릭 클라우드 공급자를 함께 사용

장점과 한계

모델장점한계
퍼블릭확장에 자본 지출 없음, 빠른 프로비전·해제, 사용한 만큼만 지불리소스·보안을 완전히 제어할 수 없음
프라이빗리소스·보안 완전 제어, 데이터가 다른 테넌트와 섞이지 않음시작·유지에 하드웨어 구매 필요, 유지 관리·업데이트 책임, 비용 높음
하이브리드가장 유연함, 앱 실행 위치 선택, 보안·규정 준수·법적 요구 제어두 환경을 함께 운영해야 함
다중 클라우드공급자별 기능 활용, 공급자 간 이전 가능여러 공급자의 리소스·보안을 각각 관리

하이브리드 활용

상황하이브리드의 대응
프라이빗 용량을 넘는 수요퍼블릭 클라우드로 확장해 흡수
보안 계층 추가민감한 시스템은 프라이빗에 유지
배치 결정앱마다 프라이빗·퍼블릭 중 실행 위치를 선택

관련 Azure 서비스

서비스내용
Azure Arc퍼블릭 Azure, 자체 데이터 센터, 하이브리드, 다중 클라우드 환경을 한곳에서 관리하는 기술 모음
Azure VMware Solution프라이빗 클라우드에서 VMware를 쓰던 조직이 VMware 워크로드를 Azure에서 그대로 실행, 통합·확장 가능
함정 · 프라이빗 클라우드가 꼭 회사 건물 안에 있어야 하는 건 아니다. 외부 데이터 센터나 타사가 호스팅해도 한 조직만 쓰면 프라이빗.

AWS비교

AzureAWS차이
Azure ArcAWS Systems Manager (하이브리드 노드), Amazon EKS AnywhereArc는 하나의 관리 계층, AWS는 서버·쿠버네티스별로 도구가 나뉨
Azure VMware SolutionAmazon Elastic VMware Service (EVS)EVS는 2025년 8월 정식 출시, 고객 VPC 안에서 VMware 환경 실행

핵심 포인트

이런 질문이 나오면답
퍼블릭과 프라이빗의 핵심 차이누구나 구매해 쓸 수 있는지 (공개 여부)
리소스·보안 완전 제어, 하드웨어 직접 구매프라이빗
자본 지출 없이 사용한 만큼 지불퍼블릭
프라이빗 용량 부족 시 퍼블릭으로 확장하이브리드
여러 퍼블릭 공급자 동시 사용다중 클라우드
여러 환경을 한곳에서 관리Azure Arc
기존 VMware 워크로드를 Azure로Azure VMware Solution

사용량 기반 모델

CapEx vs OpEx

항목CapEx (자본 지출)OpEx (운영 지출)
정의물리 인프라에 대한 일회성 선불 지출서비스·제품에 대해 시간에 따라 계속 내는 지출
예서버, 네트워크 장비, 데이터 센터 공간클라우드 사용료
클라우드해당 없음클라우드 컴퓨팅은 OpEx

기존 방식의 용량 예측 문제

예측결과바로잡으려면
크게 잡음쓰지 않는 장비에 돈을 씀이미 산 장비는 되돌릴 수 없음
작게 잡음성능 문제 발생하드웨어 주문, 전원·냉방 추가까지 시간이 걸림
클라우드피크 때 확장, 트래픽이 줄면 축소예측 부담이 사라짐

사용량 기반 모델의 이점

이점내용
선불 비용 없음장비를 미리 살 필요가 없음
유휴 인프라 없음쓰지 않는 인프라를 사고 관리할 필요가 없음
필요할 때 추가더 필요하면 더 내고 사용
필요 없으면 중지안 쓰면 더 내지 않음

종량제 요금

항목내용
방식사용한 리소스만큼만 지불
효과운영 비용 계획·관리, 효율적인 인프라 운영, 필요에 따른 확장
공급자가 맡는 것전원, 냉방, 하드웨어, 네트워킹 유지 관리
함정 · 클라우드로 옮긴다고 지출이 사라지는 건 아니다. 선불 CapEx가 사용량에 따른 OpEx로 바뀌는 것.

AWS비교

AzureAWS차이
종량제 (사용한 만큼 지불)온디맨드 요금개념 동일
OpEx 전환CapEx → OpEx 전환AWS도 클라우드의 대표 이점으로 같은 설명을 씀

핵심 포인트

이런 질문이 나오면답
서버·네트워크 장비 구매CapEx
클라우드 사용료OpEx
클라우드 비용 모델의 이름사용량 기반 모델, 종량제
용량을 작게 예측했을 때 기존 방식의 결과성능 문제, 하드웨어 추가에 시간 소요
클라우드에서 전원·냉방·하드웨어 유지 관리공급자
