NSG와 NVA

장치정체판단 기준역할
NSG보안 규칙 묶음 리소스소스·대상 IP, 포트, 프로토콜인바운드·아웃바운드 허용·거부. 우선순위 숫자가 작은 규칙부터 평가

들어오는 패킷: NSG → NVA → VM. 두 겹을 쌓으면 계층적 방어.

온프레미스 연결

항목내용
VPN신뢰할 수 없는 네트워크(주로 인터넷) 위에 암호화된 터널을 만들어 사설망끼리 연결
VPN Gateway가상 네트워크 게이트웨이의 한 유형. VNet의 전용 서브넷에 배포
제약VNet당 VPN Gateway 1개. 하나로 여러 위치(온프레미스, 다른 VNet) 연결 가능
인증VPN 유형과 관계없이 미리 공유한 키(pre-shared key)
연결 방식연결 대상경로어울리는 상황
사이트 간 (S2S)온프레미스 데이터 센터 전체인터넷 위 암호화 터널사내망과 VNet 상시 연결
지점 및 사이트 간 (P2S)개별 클라이언트 기기기기가 시작하는 암호화 연결재택·출장 중 한 사람
네트워크 간 (VNet-to-VNet)다른 VNetVPN Gateway끼리 터널VPN으로 VNet을 묶을 때
ExpressRoute온프레미스 위치연결 공급자의 전용 회로, 인터넷 미경유높은 대역폭, 일관된 지연, 규정 준수

VPN 유형

구분정책 기반경로 기반
터널로 보낼 트래픽암호화할 IP 집합을 정적으로 지정IP 라우팅(고정 경로·동적 프로토콜)으로 결정
변화에 대한 강도주소가 바뀌면 재설정새 서브넷 등 토폴로지 변화에 강함
필수인 경우—VNet 간, P2S, 다중 사이트, ExpressRoute 공존

VPN 고가용성

방식동작조건·수치
활성/대기기본 구성. 인스턴스 2개 중 대기가 자동 인계, 그동안 잠깐 끊김계획된 유지 관리 수초, 비계획 중단 90초 이내
활성/활성인스턴스마다 공용 IP, 온프레미스가 각각 터널BGP 필요, 온프레미스 장비 추가 시 더 높은 가용성

03

Azure DNS

항목내용
정의Azure 인프라로 이름 확인을 제공하는 DNS 도메인 호스팅 서비스
장점다른 Azure 서비스와 같은 자격 증명, API, 도구, 청구로 DNS 레코드 관리
이점내용
성능·신뢰성전 세계 DNS 이름 서버, 애니캐스트로 가장 가까운 서버가 응답
보안Azure Resource Manager 기반: RBAC, 활동 로그, 리소스 잠금
사용 편의성Azure·외부 리소스 DNS 모두 관리, Portal·PowerShell·CLI·REST API·SDK
사용자 지정 VNet프라이빗 DNS 도메인으로 VNet 안에서 내 도메인 이름 사용
별칭 레코드Azure 리소스를 직접 가리켜 IP가 바뀌어도 자동 반영
구분일반 A 레코드별칭 레코드
가리키는 것IP 숫자Azure 리소스 (공용 IP, Traffic Manager, CDN)
IP가 바뀌면사람이 직접 수정해석 시점에 자동 반영
함정. Azure DNS로 도메인 이름을 살 수 없음. App Service 도메인이나 타사 등록 기관에서 사고, Azure DNS에는 호스팅만.
