02

IaaS (서비스로서의 인프라)

정의

항목내용
IaaS클라우드 데이터 센터의 하드웨어를 빌리고, 그 위에서 무엇을 할지는 고객이 정하는 유형
위치클라우드 서비스 중 가장 유연한 범주
특징클라우드 리소스에 대한 제어권 최대, 운영 책임도 최대

책임 분담

담당항목
공급자하드웨어 유지 관리, 인터넷 네트워크 연결, 물리적 보안
고객운영 체제 설치·구성·유지 관리, 패치, 네트워크 구성, 데이터베이스·스토리지 구성, 많은 보안 제어, 그 밖의 모든 것

적합한 상황

시나리오내용IaaS인 이유
리프트 앤 시프트온프레미스 데이터 센터와 비슷한 클라우드 리소스를 만들고 워크로드를 그대로 옮김기존 구성을 거의 바꾸지 않고 이전
테스트·개발정해진 구성을 빠르게 복제해 개발·테스트 환경을 만들고 없앰완전한 제어를 유지하면서 빠르게 시작·종료
함정 · IaaS에서 운영 체제 패치는 공급자가 아니라 고객 책임이다. 공급자는 하드웨어, 인터넷 연결, 물리 보안까지만.

AzureAWS차이

Azure Virtual NetworkAmazon VPC고객이 직접 구성하는 네트워크
Azure MigrateAWS Application Migration Service리프트 앤 시프트 이전 도구

핵심 포인트

이런 질문이 나오면답
IaaS에서 공급자 책임하드웨어, 인터넷 연결, 물리적 보안
IaaS에서 OS 설치·패치고객
온프레미스 구성을 그대로 클라우드로IaaS (리프트 앤 시프트)
개발·테스트 환경을 빠르게 복제, 완전한 제어 유지IaaS
03

PaaS (서비스로서의 플랫폼)

정의

항목내용
PaaS데이터 센터 공간 임대(IaaS)와 완성된 솔루션 구매(SaaS)의 중간
장점운영 체제·데이터베이스의 라이선스와 패치를 신경 쓰지 않아도 됨
강점개발 인프라 유지 관리 부담 없이 완전한 개발 환경 제공

책임 분담

담당항목
공급자물리 인프라, 물리 보안, 인터넷 연결, 운영 체제, 미들웨어, 개발 도구, 분석 서비스, 관리형 런타임
고객애플리케이션 코드, 데이터, 액세스 제어
공유서비스 구성에 따라 일부 네트워킹·애플리케이션 보안 설정

적합한 상황

시나리오내용PaaS인 이유
개발 프레임워크내장 소프트웨어 구성 요소로 클라우드 앱을 개발·사용자 지정확장성, 고가용성, 멀티 테넌트 기능이 기본 포함돼 코딩량 감소
분석·비즈니스 인텔리전스데이터를 분석해 인사이트·패턴을 찾고 결과를 예측분석 도구를 서비스로 제공받아 계획·운영 결정 개선
함정 · "OS·데이터베이스 라이선스와 패치를 신경 쓰고 싶지 않은 개발팀"은 IaaS가 아니라 PaaS.

AWS비교

AzureAWS차이
Azure App ServiceAWS Elastic Beanstalk코드만 올리면 실행 환경 자동 구성
Azure SQL DatabaseAmazon RDS관리형 데이터베이스, 엔진 패치는 공급자

핵심 포인트

이런 질문이 나오면답

PaaS에서 고객이 집중하는 것앱 코드, 데이터, 액세스 제어
인프라 걱정 없는 완전한 개발 환경PaaS
데이터 분석·BI 도구를 서비스로PaaS
04

SaaS (서비스로서의 소프트웨어)

정의

항목내용
SaaS완전히 개발된 애플리케이션을 빌려 사용하는 유형. 제품 관점에서 가장 완성된 모델
예이메일, 재무 소프트웨어, 메시징 앱, 연결 소프트웨어
특징가장 덜 유연하지만 가장 쉽게 시작, 필요한 기술 지식 최소, 고객 운영 부담 최소

책임 분담

담당항목
공급자인프라, 플랫폼, 애플리케이션 유지 관리 (패치, 업데이트, 가용성)
고객데이터, ID·액세스 설정, 디바이스 접근 상태

예시와 적합한 상황

구분내용
협업 플랫폼 사용 팀사용자 온보딩, 액세스 제어, 데이터 거버넌스에 집중. 인프라 패치·앱 업데이트·가용성은 공급자
이메일·메시징메일 서버를 운영하지 않고 바로 사용
생산성 앱문서·협업 도구를 설치·관리 없이 사용
재무·경비 추적완성된 재무 앱을 구독해 사용
함정 · SaaS라도 데이터와 계정 관리는 고객 책임. 누구에게 접근 권한을 줄지는 공급자가 정해 주지 않는다.

Azure Marketplace의 SaaSAWS Marketplace의 SaaS타사 SaaS를 구독·청구 통합, 개념 동일
