02

물리적 인프라

계층정의사용자가 고르나알아둘 점
데이터 센터서버 랙, 전원, 냉각, 네트워크를 갖춘 건물아니요지역·영역으로 묶여 제공
가용성 영역지역 안에서 물리적으로 분리된 데이터 센터 묶음예독립 전원·냉각·네트워크, 광 네트워크로 연결. AZ 지원 지역은 최소 3개
지역저지연망으로 묶인 데이터 센터 1개 이상예 (대부분 배포 시)일부 VM 크기·스토리지는 지역 한정
지역 쌍같은 지리 안, 300마일 이상 떨어진 두 지역아니요 (플랫폼이 정의)지역 재해 대비
소버린 지역일반 Azure와 격리된 별도 인스턴스규정 준수 필요 시미국 정부용, 중국
글로벌 서비스. Microsoft Entra ID, Azure Traffic Manager, Azure DNS는 지역 선택이 필요 없음.

가용성 영역

서비스 분류동작예영역 장애 시
영역 서비스내가 특정 영역에 고정VM, 관리 디스크, IP 주소그 영역에 있으면 중단
영역 중복 서비스플랫폼이 영역 간 자동 복제영역 중복 스토리지(ZRS), SQL Database남은 영역에서 계속
비지역 서비스항상 사용 가능—영역·지역 장애에도 계속

영역 간 복제·데이터 전송에는 비용이 발생할 수 있음. 모든 지역이 가용성 영역을 지원하지는 않음.

지역 쌍

형태예특징
양방향 쌍미국 서부 ↔ 미국 동부, 동남아시아 ↔ 동아시아서로 백업. 대부분의 지역
단방향 쌍브라질 남부 → 미국 중남부브라질 남부만 백업을 받음. 지리 밖과 짝인 유일한 예외
쌍 없음이탈리아 북부, 폴란드 중부, 이스라엘 중부가용성 영역 + 지역 중복 스토리지로 복원력 확보
지역 쌍의 이점내용
복구 우선순위대규모 장애 시 쌍마다 한 지역을 우선 복구
업데이트 순서계획된 업데이트를 쌍 중 한 지역씩 순차 적용
데이터 상주데이터가 같은 지리 안에 머묾 (브라질 남부 제외)
주의자동 복제·장애 조치를 하지 않는 서비스는 고객이 직접 구성
용어 함정. 영역 중복 스토리지(ZRS) = 한 지역 안 여러 영역. 지역 중복 스토리지(GRS) = 다른 지역까지.

소버린 지역

계열지역 예운영특징
미국 정부용US DoD Central, US Gov 버지니아, US Gov 애리조나검증된 미국인물리적·논리적 네트워크 격리, 추가 규정 준수 인증
중국중국 동부, 중국 북부21VianetMicrosoft가 데이터 센터를 직접 운영하지 않음

03

관리 인프라

리소스와 리소스 그룹

항목내용
리소스만들고 배포하는 모든 것 (VM, 가상 네트워크, DB, Azure AI 서비스)
리소스 그룹리소스의 묶음. 모든 리소스는 정확히 하나의 그룹에 속함
규칙 1한 번에 한 그룹에만 소속. 일부 리소스는 다른 그룹으로 이동 가능
규칙 2그룹 안에 그룹 중첩 불가, 만든 뒤 이름 변경 불가 → 처음부터 명명 규칙
규칙 3그룹에 한 작업은 안의 모든 리소스에 적용. 삭제하면 전부 삭제, 권한도 전부에 적용
활용 패턴방법효과
임시 개발 환경한 그룹에 몰아넣기끝나면 그룹째 삭제
프로젝트별 분리프로젝트마다 그룹 생성팀이 자기 리소스만 보고 관리

구성 방식에 정답은 없음. 상황에 맞게 선택.

구독

항목내용
정의관리·청구·확장의 단위. Azure를 쓰려면 반드시 필요
연결Entra ID(또는 Entra ID가 신뢰하는 디렉터리)의 ID인 Azure 계정에 연결
청구 경계구독마다 별도 청구 보고서·청구서
액세스 제어 경계접근 관리 정책이 구독 수준에서 적용. 구독마다 지출 한도·접근 규칙이 다를 수 있음
구독을 나누는 기준예이유
환경샌드박스, 개발, 테스트, 프로덕션접근 제어가 구독 수준이라 자연스러운 경계
팀·워크로드프로젝트마다 구독비용 추적, 샌드박스와 프로덕션 분리
청구프로덕션용, 개발·테스트용비용을 따로 추적

항목내용

테넌트 루트 그룹Entra 테넌트당 하나뿐인 최상위 그룹. 모든 관리 그룹·구독이 그 안에
수치값
