Azure RBAC

개념정의
최소 권한 원칙작업에 필요한 최소한의 권한만 부여
역할관련 권한의 묶음. 기본 제공 + 사용자 지정
범위관리 그룹 → 구독 → 리소스 그룹 → 리소스
상속부모 범위의 권한이 모든 자식 범위로 자동 전파
허용 모델역할이 허용한 작업만 가능, 역할이 겹치면 권한이 합쳐짐
적용 대상Azure Resource Manager를 통하는 작업 (Portal, Cloud Shell, PowerShell, CLI)
적용되지 않는 곳애플리케이션·데이터 수준 접근
역할보기만들기·관리권한 주기주로 받는 사람
소유자가능가능가능관리자
기여자가능가능불가엔지니어, 운영자
읽기 권한자가능불가불가관찰자, 감사 담당
1번 모듈과 연결. 관리 그룹에 RBAC를 한 번 걸면 아래 전부에 상속. RBAC(무엇을 할 수 있나)와 Azure Policy(리소스가 지킬 규칙)는 별개라 소유자도 정책 위반 리소스는 만들 수 없음.

보안

제로 트러스트

원칙의미실천 방법
명시적으로 확인항상 인증·권한 부여, 모든 데이터 요소를 근거로ID, 위치, 기기 상태, 위험 신호로 검증
최소 권한 액세스필요한 만큼만 접근JIT, JEA, 위험 기반 적응형 정책, 데이터 보호
위반 가정이미 뚫렸다고 보고 피해 범위 축소구간 분할, 엔드투엔드 암호화, 가시성 확보, 위협 탐지
구분경계 기반제로 트러스트
신뢰 기준내부 네트워크면 신뢰위치와 상관없이 모두 검증
기기회사 관리 PC만 연결기기 상태를 계속 평가
원격 접속엄격한 VPN인증과 상황에 따라 결정
개인 기기자주 차단조건 충족 시 허용

심층 방어

계층목적대표 수단
1. 물리적 보안하드웨어 물리 접근 차단, 첫 방어선데이터 센터 출입 통제
2. ID 및 액세스인프라 접근·변경 통제SSO, MFA, 감사
3. 경계대규모 네트워크 공격 필터링·경고DDoS 방어, 경계 방화벽
4. 네트워크필요한 통신만 허용, 확산 방지통신 제한, 기본 거부, 인바운드 인터넷 차단, 보안 연결
5. 컴퓨팅맬웨어·미패치 노출 최소화VM 접근 보호, 엔드포인트 보호, 패치
6. 애플리케이션코드 취약점 제거보안 개발 수명 주기, 비밀은 Key Vault에
7. 데이터기밀성·무결성·가용성저장·전송 암호화, 키 관리, 규제 충족

Microsoft Defender for Cloud

보호 대상방법내용
Azure기본 통합PaaS 위협 탐지, 데이터 서비스 평가, 네트워크 노출 감소
온프레미스Azure Arc 배포Azure가 아닌 서버로 보호 확장
다른 클라우드AWS·GCP 연결AWS CSPM·규정 준수 평가, EKS·EC2 보호, 에이전트 없는 평가
단계하는 일핵심
1. 지속적 평가취약점 찾기·추적VM, 컨테이너 레지스트리, SQL 서버. 서버용 Defender는 엔드포인트용 Defender와 자동 통합
2. 보안모범 사례로 강화Azure Policy 기반(관리 그룹·구독·테넌트), 새 리소스 자동 평가, MCSB 기준 권장 사항
3. 방어위협 탐지·대응보안 경고, 고급 위협 방지 (VM, SQL, 컨테이너, 웹앱, 네트워크)
기능설명
보안 점수권장 사항을 보안 컨트롤로 묶어 계산, 현재 수준 파악과 우선순위 결정
권장 사항MCSB 기준으로 우선순위를 매겨 제시
보안 경고영향 리소스 설명, 해결 단계, Logic Apps 자동 대응, 내보내기
킬 체인 분석관련 경고를 엮어 공격 시작점·영향 리소스·전체 흐름 제시
