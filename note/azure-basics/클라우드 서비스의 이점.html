02

안정성과 예측 가능성

안정성

항목내용
안정성장애에서 복구하고 계속 동작하는 능력
위치Azure Well-Architected Framework의 기둥 중 하나
클라우드의 강점분산 설계로 전 세계 여러 지역에 배포 가능
지역 장애 시다른 지역에서 계속 실행, 경우에 따라 자동으로 다른 지역으로 전환

예측 가능성

구분목표수단
성능 예측좋은 고객 경험에 필요한 리소스를 예측자동 크기 조정, 부하 분산, 고가용성
비용 예측클라우드 지출을 예측하고 계획실시간 리소스 사용 추적, 모니터링, 데이터 분석(패턴·추세), Azure 가격 계산기
수단역할
자동 크기 조정수요에 맞춰 리소스를 자동으로 늘리고 줄임
부하 분산트래픽을 여러 리소스에 나눠 과부하를 막음
사용량 분석패턴과 추세를 찾아 앞으로의 비용을 예측
Azure 가격 계산기배포 전에 예상 비용을 추정
Well-Architected Framework성능·비용 예측 모두에 영향을 주는 설계 지침
함정 · 안정성(장애 후 회복)과 고가용성(중단 없이 사용)은 비슷하지만 다르다. 문제에 "복구", "장애에서 회복"이 나오면 안정성.

03

보안과 거버넌스

거버넌스

기능내용
템플릿배포한 리소스가 회사 표준과 규정 요구 사항을 따르도록 보장
일괄 업데이트표준이 바뀌면 기존 리소스를 대규모로 한 번에 갱신
클라우드 감사회사 표준을 벗어난 리소스를 표시하고 완화 전략 제시
자동 패치운영 모델에 따라 소프트웨어 패치·보안 업데이트 자동 적용

보안: 모델별 제어 범위

모델보안 제어패치·유지 관리맞는 경우
IaaS최대 (OS와 설치 소프트웨어까지 직접)고객이 직접보안을 최대한 직접 통제하고 싶을 때
PaaS, SaaS제한적자동 처리패치·유지 관리 부담을 줄이고 싶을 때
위협클라우드의 대응
DDoS 공격클라우드 공급자는 대규모 인프라로 DDoS 공격 대응에 유리
물리적 위협공급자가 데이터 센터 물리 보안을 담당
함정 · "보안 제어를 가장 많이 원한다"면 IaaS. 대신 패치도 직접 해야 한다. "패치를 자동으로"는 PaaS·SaaS.

관리 효율성과 지속 가능성

관리 효율성

유형뜻예
클라우드의 관리클라우드 리소스 자체를 관리하는 기능자동 크기 조정, 템플릿 배포, 상태 모니터링·자동 교체, 메트릭 경고
클라우드에서의 관리클라우드 환경과 리소스에 접근해 관리하는 방법웹 포털, CLI, API, PowerShell
예시 운영 흐름사용 방법효과
1. 리소스 배포템플릿구성 일관성
2. 상태 확인포털에서 모니터링한눈에 파악
3. 반복 작업CLI, PowerShell 스크립트수동 작업 감소

지속 가능성

항목내용
지속 가능성리소스 배포·사용 방법을 적극 최적화할 때 클라우드가 지속 가능성 목표를 지원
규모의 효과대규모로 운영하는 공급자는 흩어진 온프레미스 환경보다 리소스 사용률을 높일 수 있음
수요 맞춤배포한 리소스를 실제 수요에 맞춰 낭비를 줄임
실천 방법효과
수요가 줄면 리소스 축소필요 이상 가동 방지
쓰지 않는 리소스 해제·할당 취소유휴 리소스의 에너지·비용 소모 제거
효율적인 서비스·구성 선택과다 프로비저닝 감소
거버넌스·모니터링 활용사용 추세를 추적해 계속 최적화
함정 · 지속 가능성과 비용 절감은 같은 방향이다. 쓰지 않는 리소스를 끄면 둘 다 좋아진다.
