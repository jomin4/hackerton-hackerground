02

Azure Policy

할당 범위와 평가

동작언제결과
생성·변경 시 평가새 리소스를 만들거나 기존 리소스를 바꿀 때비준수 구성이면 생성·변경 차단 가능 (예: VM 생성과 크기 조정 모두 검사)
기존 리소스 평가정책을 만들기 전부터 있던 리소스평가·모니터링해 비준수로 강조. 삭제하지는 않음
수정 (Remediation)일부 정책비준수 리소스를 자동으로 바로잡음 (예: AppName 태그가 없으면 추가)
예외특정 리소스만 빼고 싶을 때해당 리소스를 정책 평가 대상에서 제외
상속상위 범위에 할당개별 리소스 ← 리소스 그룹 ← 구독. 그 안에 새로 만드는 리소스도 자동 적용

이니셔티브

개념정의
Azure Policy리소스 구성 규칙을 만들고 할당·관리해 표준을 강제하거나 감사하는 서비스
정책 정의리소스 구성에 대한 개별 규칙
이니셔티브관련 정책 정의를 묶어 더 큰 목표의 준수 상태를 추적
기본 제공 정의스토리지, 네트워킹, 컴퓨팅, 보안, 모니터링 영역
DevOps 통합Azure DevOps CI/CD 파이프라인의 배포 전·후 단계에서 정책 검사
AI 지원 변경Copilot 권장이나 에이전트가 제안한 변경에도 같은 표준 적용 (허용 위치, 필수 태그, 승인된 SKU, 보안 기준)
RBAC와 다름. RBAC는 "누가 무엇을 할 수 있나", Azure Policy는 "리소스가 어떤 상태여야 하나". 소유자 권한이 있어도 정책을 어기는 리소스는 만들 수 없음.

AzureAWS차이
정책 평가·비준수 표시·수정AWS Config 규칙 + 자동 수정Config는 이미 만든 리소스를 감지
거부 (생성 차단)서비스 제어 정책 (SCP)AWS는 예방을 Organizations에서 따로 처리
이니셔티브Config 적합성 팩 (Conformance Packs)규칙 묶음 개념 동일
Azure Policy 하나Config + SCP 조합Azure는 예방과 감지·수정이 한 서비스

리소스 잠금

잠금 종류읽기수정삭제한 줄 정리
Delete가능가능불가지우는 것만 막음
ReadOnly가능불가불가모든 사용자를 읽기 권한자로 제한한 것과 비슷
항목내용
목적권한 있는 사용자가 중요한 리소스를 실수로 삭제·변경하는 위험 감소
적용 범위개별 리소스, 리소스 그룹, 구독
상속리소스 그룹에 걸면 그 안의 모든 리소스에 적용
관리 도구Portal (리소스 설정의 잠금 메뉴), PowerShell, Azure CLI, ARM 템플릿
RBAC와 관계RBAC 권한과 상관없이 적용. 소유자도 막힘
잠긴 리소스 변경 절차작업
1. 잠금 제거잠금을 먼저 삭제
2. 작업 수행내 권한으로 할 수 있는 작업을 실행
잠금은 "실수" 방지용. 권한 있는 사람이 두 단계를 거치면 바꿀 수 있음. 누가 할 수 있는지를 제한하는 것은 RBAC의 몫.

AWS비교

AzureAWS차이
Delete 잠금EC2 종료 방지, RDS 삭제 방지, CloudFormation 스택 종료 방지AWS는 서비스마다 따로 설정, 범위 상속 없음
ReadOnly 잠금단일 기능 없음 (IAM·SCP 명시적 Deny로 구현)Azure는 리소스 그룹·구독 단위로 한 번에
소유자도 막힘명시적 Deny는 관리자 권한도 막음막는 효과는 비슷, 해제 방식이 다름

Service Trust Portal

항목내용
정의Microsoft의 보안·개인 정보 보호·규정 준수 관행에 관한 콘텐츠, 도구, 리소스를 모은 포털
담긴 내용클라우드 서비스와 고객 데이터를 보호하는 Microsoft의 제어·프로세스 구현 세부 정보
주소servicetrust.microsoft.com
접근 조건일부 리소스는 Microsoft Entra 회사·학교 계정으로 로그인 + 규정 준수 자료 비공개 계약(NDA) 동의
보관 기간게시 후 12개월 이상 또는 새 버전이 나올 때까지 다운로드 가능
주 메뉴용도
Service Trust Portal홈으로 돌아가는 바로가기
내 라이브러리저장(고정)한 문서 모음. 문서가 업데이트되면 알림 설정 가능
모든 문서포털 문서를 한곳에서 검색. 여기서 고정하면 내 라이브러리에 표시
