Azure와 상호 작용하는 도구

도구 비교

도구형태강점알아둘 점
Azure Portal웹 기반 GUI클릭으로 리소스 생성·관리, 사용자 지정 대시보드, 접근성 옵션모든 Azure 데이터센터에 배포되어 복원력이 높고 사용자 가까이에서 응답. 유지 관리 다운타임 없이 계속 업데이트
Azure Cloud Shell브라우저 기반 셸설치·구성 없이 바로 명령 실행Portal의 Cloud Shell 아이콘으로 실행. Azure 자격 증명으로 이미 인증됨. PowerShell 또는 Bash 선택
Azure PowerShellcmdlet 모음한 번 실행하는 작업부터 수백 개 리소스 오케스트레이션까지cmdlet이 Azure REST API를 호출. 스크립트로 저장해 반복·자동화. Windows·Linux·macOS 또는 Cloud Shell
Azure CLI명령줄 도구 (Bash 문법)PowerShell과 기능 동등차이는 명령 문법뿐. 익숙한 쪽을 쓰면 됨
Copilot in Azure자연어 도우미질문 답변, 여러 단계에 걸친 작업 수행운영 환경 적용 전 결과 검증, 권한 확인, 변경 내용 검토
함정 Cloud Shell과 Azure CLI는 대립 관계가 아니다. Cloud Shell은 브라우저 안의 실행 환경이고, 그 안에서 Azure PowerShell이나 Azure CLI를 실행한다.

Azure 밖에 있는 리소스를 Azure Resource Manager에 투영해, Azure 안의 리소스처럼 한곳에서 관리한다.

Arc로 관리할 수 있는 리소스 (Azure 외부 호스팅)

리소스내용

Kubernetes 클러스터어디서 실행되든 Azure에서 구성·관리
Azure 데이터 서비스Azure 데이터 서비스를 내 인프라에서 실행

가상 머신미리 보기 단계

Arc가 주는 것

이점내용
통합 관리비Azure 리소스를 ARM에 투영해 환경 전체를 함께 관리
Azure처럼 관리멀티클라우드·하이브리드의 VM, Kubernetes 클러스터, 데이터베이스를 Azure에서 실행되는 것처럼 관리
익숙한 도구리소스 위치와 관계없이 익숙한 Azure 서비스·관리 기능 사용
점진적 전환기존 ITOps를 유지하면서 DevOps 방식 도입
사용자 지정 위치Arc 지원 Kubernetes 클러스터 위에 추상화 계층을 구성
함정 Arc는 Azure 하드웨어를 내 데이터센터에 들여놓는 것이 아니다. 이미 있는 외부 리소스를 Azure 관리 체계에 연결하는 다리.

03

Azure Resource Manager (ARM)

Azure의 배포·관리 서비스. 어떤 도구로 요청하든 모두 Resource Manager를 거친다.

ARM의 이점

이점내용
선언적 템플릿스크립트 대신 템플릿(JSON)으로 인프라 관리
그룹 단위솔루션의 리소스를 하나씩이 아니라 그룹으로 배포·관리·모니터링
일관된 재배포개발 수명 주기 내내 다시 배포해도 일관된 상태
종속성리소스 간 종속성을 정의해 올바른 순서로 배포
액세스 제어RBAC가 관리 플랫폼에 기본 통합되어 모든 서비스에 적용
태그리소스에 태그를 붙여 구독 안 리소스를 논리적으로 정리
비용 확인같은 태그를 공유하는 리소스 그룹의 비용을 모아 봄

AWS비교

AzureAWS차이
Azure Resource Manager서비스별 API + IAM 인증AWS에는 ARM처럼 이름 붙은 단일 관리 계층이 없음
RBAC 기본 통합모든 API 호출에 IAM 정책 평가요청마다 권한을 확인한다는 점은 같음
리소스 그룹 (함께 배포·삭제)CloudFormation 스택Azure는 리소스가 반드시 하나의 리소스 그룹에 속함
태그로 비용 정리태그 + 비용 할당 태그AWS는 결제 콘솔에서 비용 할당 태그로 활성화해야 비용 보고서에 나타남

04

IaC · ARM 템플릿 · Bicep

IaC(코드형 인프라)는 인프라를 코드 줄로 관리하는 개념. CLI·PowerShell 스크립트로 시작할 수 있고, ARM 템플릿과 Bicep은 원하는 최종 상태를 선언해 반복 배포를 한 단계 더 끌어올린다.

명령형 스크립트 vs 선언형 템플릿

항목스크립트 (CLI·PowerShell)ARM 템플릿 · Bicep
작성 내용무엇을 어떤 순서로 실행할지원하는 최종 상태
배포 순서작성자가 책임Resource Manager가 종속성으로 결정, 가능하면 병렬
다시 실행이미 있는 리소스 처리도 작성자가 고려멱등성: 여러 번 배포해도 같은 상태
사전 확인실행해 봐야 앎배포 전에 템플릿 유효성 검사

ARM 템플릿

이점내용
선언적 구문JSON으로 배포할 인프라를 선언. 프로그래밍 명령 순서를 쓰지 않음
반복 가능한 결과개발 수명 주기 내내 같은 템플릿을 여러 번 배포해도 일관된 상태 (멱등성)
오케스트레이션상호 의존 리소스를 올바른 순서로, 가능하면 병렬로 배포
모듈식 파일작은 재사용 템플릿으로 나누고 배포 시 연결 (중첩 템플릿)
확장성배포 스크립트로 템플릿 안에서 PowerShell·Bash 실행

Bicep

이점내용
모든 리소스 지원모든 리소스 종류와 API 버전(미리 보기 포함)을 즉시 지원
간단한 구문같은 JSON 템플릿보다 짧고 읽기 쉬움. 프로그래밍 언어 지식 불필요
반복 가능한 결과멱등성. 여러 번 배포해도 같은 상태
오케스트레이션상호 의존 리소스를 올바른 순서로, 가능하면 병렬로
모듈성모듈로 코드를 나눠 재사용
함정 Bicep은 ARM을 대체하는 별도 배포 엔진이 아니다. 둘 다 Resource Manager가 배포하고, 차이는 작성 언어(JSON vs Bicep)뿐.

AWS비교

AzureAWS차이
ARM 템플릿 (JSON)CloudFormation 템플릿둘 다 선언형. CloudFormation은 JSON·YAML 모두 지원
BicepCloudFormation YAML · AWS CDKBicep은 전용 선언형 언어. CDK는 일반 프로그래밍 언어로 작성해 CloudFormation 템플릿으로 변환
중첩 템플릿 · Bicep 모듈중첩 스택재사용 단위로 쪼개는 개념은 같음
배포 스크립트CloudFormation 사용자 지정 리소스Azure는 PowerShell·Bash 스크립트, AWS는 주로 Lambda 함수로 추가 작업
